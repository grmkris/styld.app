# Delivery plan

Objective: deliver Styld v2 on the researched stack and tooling patterns with the v1 behaviour worth keeping, a testable workers.dev deployment and multiple final review rounds. The owner decided the kept and parked scope and the iteration order on 2026-10-29 (`docs/ROADMAP.md`); v1 parity is no longer the goal. No smaller prototype substitutes for a kept feature.

## Baseline

V1 repository: `/home/kristjan/code/stylelab`. Frozen comparison commit: `dddf9d44b656701282debd2ff88b343851145126`. `docs/migration/v1-inventory.json` records tracked page, route, router, worker, schema, MCP and behavioral-test paths with content hashes; `docs/migration/v1-features.md` lists v1's behaviour by feature id and `docs/migration/v1-usage-2026-10-29.md` its production use. Later v1 changes are reviewed explicitly before adding to this baseline.

## Work sequence

1. Foundation: exact dependency family, tsrs/effect-tsrs, verified tsrs-lint, Oxfmt/Oxlint/anti-slop, graph/provenance/suppression gates, skills/MCP, tests and reproducible build.
2. Runtime proof: Alchemy isolated preview, D1/Drizzle, R2, native telemetry, Foldkit SSR + client, en/sl, Yielded sessions, Domain reservation/job through a native Worker test. Native acceptance now exercises the actual application Worker and the built Foldkit website through the public edge, including browser hydration, locale persistence, and unauthenticated session reads with Origin/CSRF enforcement. The isolated preview and native telemetry readback are accepted at the release recorded in STATUS; signed-in flows and job recovery remain pending.
3. Build the kept rows below in the iteration order of `docs/ROADMAP.md`. Where a kept row ports v1 behaviour, preserve its rules, not just its route names; where the roadmap changes the behaviour, the roadmap wins. Land coherent tested slices.
4. Connect provider adapters with metering, durable retries/refunds and unknown-outcome handling; exercise storage/restart/privacy failure cases.
5. Before go-live, rehearse the import of real v1 wardrobes with fixtures; verify image delivery, locale, mobile and MCP contracts.
6. Deploy clean tested releases to workers.dev; verify the actual release and end-to-end flows. Run architecture/tooling, correctness/security, and product/browser review rounds, fix findings, rerun final gates.

## Proof levels

Record unit/property, native workerd, deployed preview, browser and real-provider results separately. A source manifest, green build or stub response does not prove a feature. Final sign-off requires implementation paths and behavioral evidence for every kept row.

## Completion conditions

All kept rows accepted; zero unresolved high/medium review findings; pinned and effective quality gates; full build/tests and native/deployed acceptance at the final commit; isolated Worker URL and release readback; clean owned worktree; no production changes without the owner's go; documented remaining owner-specific connector approvals if a client requires interactive login, without calling those acceptance tests passed.
